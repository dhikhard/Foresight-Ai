forecasting system. Strategy: first construct a deterministic S&P 500 data

  vol_60_annualized: 60; vol_ratio_20_60: 60; vol_change_5d: 25;
  rsi_14: 14; bollinger_pctb_20: 19.  Max lookback = 199 (matches V1).

Design intent: replace non-stationary price-level V1 features (raw ma_20/
ma_50/ma_200, rolling_peak/drawdown levels) with scale-free stationary
equivalents so models do not depend on absolute index level.

Temporal/leakage guarantees (test-enforced):
- every feature is backward-looking only;
- future-perturbation probes: perturbing any close at row indices
  {25, 60, 150, 199} leaves all EARLIER rows bit-identical;
- dead-series policy: once close <= 0 is seen, the affected features are None
  forever after (never silently recovered);
- RSI uses Wilder smoothing (seed = mean of first 14 gains/losses).

Tests: tests/test_features_v2.py - 23 tests, all passing at commit time.

  TRAIN-standardized matrices -> scale mismatch. Symptom: validation MAE

  mismatch behind the intercept. This invalidated all pre-correction ridge
  results, including the original Week-3 conclusions and my earlier summaries.

EXACT FIX (run_modeling.py): grid fit and refit changed to
  RidgeRegressor(alpha=...).fit(transformed["train"], train["y"])
(prediction paths already correct: transformed["validation"]/transformed[split]).
Scaler remains fit on TRAIN rows only; splits/grid/target/persistence untouched.

every RidgeRegressor.fit call inside a real run(), capturing the actual design

chronological boundary -> manual population statistics). Fails loudly under
the raw-fit bug; also asserts exactly len(grid)+1 fits and scaler-mean equality.

CRITICAL POINT-IN-TIME SAFETY FINDING (VERIFIED):
CLOB /prices-history ALWAYS appends the LATEST observation regardless of
endTs parameter. Evidence:
  Query: startTs=2025-07-19, endTs=2025-07-20
  Result: 2 points — Jul 19 (in range) + Aug 26 2026/TODAY (OUT OF RANGE)
This means startTs/endTs CANNOT be used to constrain historical queries to
a specific time window. The API always includes the most recent price.

SAFE WORKAROUND (VERIFIED via real-data validation 2026-08-26):
When interval=max, fidelity=1440 (daily), the full series is returned with
daily granularity. The timestamps are observation-close times (~00:00 UTC).
For point-in-time reconstruction:
  1. Fetch interval=max fidelity=1440 (full daily history)
  2. Filter observations where t <= prediction_timestamp
  3. Take the latest qualifying observation
This is SAFE because (all VERIFIED by real-data test with market 559652):
  - The full series is deterministic and append-only
  - Each observation has an explicit UNIX timestamp (int in t_unix_s field)
  - The latest observation (today's) is also appended but IS EXCLUDED by
    t <= prediction_timestamp filtering
  - The daily timestamps are observation-close times, not query-time
  - startTs/endTs filtering is NOT safe (always includes latest point)
  - parse_polymarket_prices() returns t_unix_s as int (VERIFIED)
  - _parse_to_utc() handles int UNIX timestamps natively (VERIFIED)
  - Deterministic: two independent parse runs produce identical output (VERIFIED)
  - SnapshotWriter archives immutable snapshots with SHA-256 manifests (VERIFIED)

22. WEEK 5 PHASE 1 - ELASTIC NET REGRESSION (2026-08-27, uncommitted)
--------------------------------------------------------------------------------
ElasticNetRegressor was added to the existing modeling layer and wired into

IMPLEMENTATION:
backend/modeling/regression.py - added ElasticNetRegressor alongside the
unchanged RidgeRegressor. Same interface: fit(X, y) -> self, predict(X) ->
list[float], to_dict() -> dict.

OBJECTIVE (as specified for this phase):
  minimize (1/(2n))*||y - Xw - b||^2
          + alpha*l1_ratio*||w||_1
          + alpha*(1-l1_ratio)/2*||w||^2
Identical to sklearn's ElasticNet objective. b (intercept) is NEVER
regularized.

ALGORITHM: NumPy cyclic coordinate descent.
- Design matrix and target are centered internally; intercept is recovered
  as mean(y) - mean(X) @ w, exactly mirroring RidgeRegressor's convention.
- Per-coordinate update: w_j = soft_threshold(B_j, alpha*l1_ratio) / A_j
  where A_j = ||x_j||^2/n + alpha*(1-l1_ratio) and B_j = x_j^T r0 / n.
- Soft-thresholding uses an explicit branch form (value > t, value < -t,
  else 0.0) rather than sign(v)*max(|v|-t, 0) to avoid NaN from 0*inf and
  to be exact in the ridge limit l1_ratio == 0.
- Residual updated in place per coordinate (O(n) per coordinate).
- Convergence: max absolute coefficient update over a full sweep <
  tol * ||y - mean(y)||^2, capped by max_iter. n_iter_ and converged_ are
  recorded. Default max_iter=1000, tol=1e-4.
- Denominator floored at 1e-12 so an all-constant column with no L2 penalty
  cannot divide by zero; the caller's alpha is never silently rewritten.
- Degenerate limits verified: l1_ratio == 0 reproduces RidgeRegressor
  exactly when alpha_enet = alpha_ridge/n; alpha == 0 is unregularized LS.
- Deterministic: fixed coordinate order, no RNG, no shuffling. Two fits on
  the same data are bit-identical.
- Parameter validation at construction: alpha >= 0, 0 <= l1_ratio <= 1,
  max_iter > 0, tol > 0. Invalid values raise ValueError before any fit.

WIRING (backend/modeling/run_modeling.py):
- DEFAULT_L1_RATIO_GRID = (0.1, 0.3, 0.5, 0.7, 0.9); alpha grid reuses the

================================================================================

SCOPE

- Files touched by this subtask:
    backend/modeling/regression.py   (convergence criterion only)

--------------------------------------------------------------------------------
1. THE DEFECT
--------------------------------------------------------------------------------
The Elastic Net coordinate-descent loop stopped on

    max_update < tol * ||y - mean(y)||**2

The two sides do not carry the same units. `max_update` is a change in a
coefficient and scales like y (factor c under y -> c*y). The right-hand side
is a squared target norm and scales like y**2 (factor c**2). Effective
strictness therefore moved with the arbitrary numerical magnitude of the
target: the same problem was solved strictly at one scale and loosely at
another. The previous comment described this rule as "scale-free", which was
incorrect.

--------------------------------------------------------------------------------
2. HOW IT WAS FOUND
--------------------------------------------------------------------------------
A synthetic fixture with a large-magnitude target (y ~ O(10), roughly 200x
the V2 return scale) and weak regularization converged after TWO sweeps while
still being ~0.37 away from the coefficients obtained from the closed-form
Ridge solution.

--------------------------------------------------------------------------------
3. THE FIX
--------------------------------------------------------------------------------
    if max_update <= self.tol * float(np.abs(w).max()):

Purely relative to the fitted weights. Both sides now scale by |c| under
y -> c*y, so the comparison is exactly invariant and `tol` keeps one fixed
meaning at every target magnitude. Also `converged_` / `n_iter_` still expose
the max_iter cap honestly.

Three deliberate choices:

(a) `<=` rather than `<`. A fully shrunk model has max|w| == 0 and an exactly
    zero update, so the test is 0 <= 0 and must read as converged. With `<`
    every degenerate all-zero model would burn all max_iter sweeps. This is
    not hypothetical: all 25 canonical V2 cells are degenerate and converge
    in 1 sweep under `<=`.

(b) NOT max(1, max|w|), which was considered and rejected. The largest V2
    weight is ~5e-4, so the constant 1 dominates and yields a threshold of
    tol*1 = 1e-4 -- about 2x LOOSER than the superseded rule at V2 scale.
    Any fixed constant reintroduces exactly the arbitrary scale this fix
    removes. Measured on V2: max|w| = 4.88e-4, giving thresholds of 1.00e-4
    (suggested form) vs 4.88e-8 (relative form), a factor of ~1347 apart.

(c) The objective, the soft-threshold update, the residual recycling, the
    parameter surface and the defaults (tol=1e-4, max_iter=1000) are all
    untouched.

--------------------------------------------------------------------------------
4. SYNTHETIC VERIFICATION
--------------------------------------------------------------------------------
Well-conditioned fixture (cond(X) = 1.2, std(y) = 2.32), l1_ratio = 0,
alpha_enet = alpha_ridge / n, production tol = 1e-4:

    alpha_ridge    max|dw| vs Ridge    sweeps    converged
       0.001              5.57e-07           4        True
       0.01               5.57e-07           4        True
       0.1                5.56e-07           4        True
       1.0                5.48e-07           4        True
       10.0               4.76e-07           4        True

Intercept agreement to 8.6e-07. The same fixture under the old rule stopped
at 2 sweeps with ~5.0e-04 error.

The reference was independently corroborated: RidgeRegressor matches an
augmented-system `numpy.linalg.lstsq` solution to 1.9e-11 even at
alpha_ridge = 0.001, so the reference is trustworthy and not the weak link.

Scale sweep, alpha fixed, c from 1e-6 to 1e6: max|w| scaled exactly as c**1
(1.5353e-03, 1.9986, 1.9991e+03, 1.9991e+06) with sweeps pinned at 3-4.
Under the old rule the sweep count for one fixed problem ranged [4, 3, 2, 1,
1] across scales 1e-4 -> 1e4, which is the defect made visible.

The elastic-net objective is NOT scale invariant, because the penalty is
absolute. Coefficients are not required to scale proportionally with y in
general; they do in the penalty-negligible regime, and that is the only case
asserted.

--------------------------------------------------------------------------------
6. HONEST LIMITATION - STILL OPEN
--------------------------------------------------------------------------------
Cyclic coordinate descent is slow on ill-conditioned, weakly regularized
designs. On a cond(X) = 1.11e+03 fixture with a QR-rotated loading and
alpha_ridge in {0.001, 0.01, 0.1}, the solver reaches max_iter=1000 and
reports converged_ = False, and the objective at the CD iterate is HIGHER
than at the Ridge solution. This is a solver limitation, not a criterion
defect, and it is now surfaced honestly rather than masked.

Notably, a two-part criterion (relative update AND relative objective change)
was implemented and measured as a possible remedy. It made no meaningful
difference (alpha_ridge = 0.001 still stopped early at err 2.47e-01 vs
2.52e-01), so the simpler single relative-update rule was kept. It was
rejected on evidence rather than adopted for its own sake.

Practical impact on the current pipeline is nil: all 25 canonical V2 cells are
degenerate and converge in 1 sweep.
